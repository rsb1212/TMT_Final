# TMT IDEM Login Issue Analysis

## Current Issue

After successful IDEM login, the application redirects back to the login page instead of navigating to the dashboard.

---

## Browser Errors

```text
Access to XMLHttpRequest at
'https://secure-sso-rhsso-np.apps.ocplife-np.bajajlife.com/auth/realms/internal/protocol/openid-connect/token'
from origin 'http://10.3.41.102'
has been blocked by CORS policy:
No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

```text
Keycloak init failed: undefined
```

```text
POST /protocol/openid-connect/token
net::ERR_FAILED 200 (OK)
```

---

## Frontend Debug Logs

```text
AUTHENTICATED = false
KEYCLOAK AUTH = false
KEYCLOAK TOKEN = undefined
NOT AUTHENTICATED
```

---

## Impact

Because Keycloak authentication is not established:

```text
authenticated = false
```

The following code never executes:

```javascript
await exchangeKeycloakToken();
```

As a result:

```text
POST /api/v1/auth/keycloak-login
```

is never called.

Backend logs confirm:

```text
KEYCLOAK LOGIN API CALLED
```

Not Found

```text
========== IDEM LOGIN START ==========
```

Not Found

---

## Suspected Root Cause

Keycloak/RHSSO client CORS configuration issue.

Response headers from token endpoint are missing:

```http
Access-Control-Allow-Origin
```

which prevents the browser from reading the token response.
